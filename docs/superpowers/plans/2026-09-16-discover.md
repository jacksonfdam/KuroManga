# Discover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One screen at `/discover` holding everything waiting on a decision, ordered so the items closest to done come first.

**Architecture:** A read model over three existing sources. `GET /api/discover` runs the existing `collapsed_anime()` assembly, fetches suggestions and review items with their own SQL, merges them into one item shape, ranks by distance to done and pages — all in the API process. Every write keeps its current endpoint.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2.0 async, asyncpg, Postgres 17; React 19, React Router 7, Tailwind.

**Spec:** `docs/superpowers/specs/2026-09-16-discover-design.md`

```python
and the handful that are one click from done are buried, and the screen is
useless on its first day.

from app.discover.feed import DiscoverItem, Need, rank_of, sort_key


def item(**kw) -> DiscoverItem:
    base = dict(
        kind="suggestion", id=1, series_id=None, title="A work", cover_url=None,
        why="", needs=[Need.SOURCE], candidates=[], confident=False,
        rank_score=0.0, candidate_count=0, finished=False,
    )
    base.update(kw)
    return DiscoverItem(**base)


def test_a_confident_single_step_ranks_first():
    assert rank_of(item(needs=[Need.SOURCE], confident=True)) == 1


def test_an_ambiguous_single_step_ranks_second():
    assert rank_of(item(needs=[Need.SOURCE], confident=False, candidate_count=3)) == 2


def test_a_dead_end_ranks_below_an_ambiguous_one():
    """It looks like one step and is the most work in the list."""
    dead_end = item(needs=[Need.SOURCE], confident=False, candidate_count=0)
    ambiguous = item(needs=[Need.SOURCE], confident=False, candidate_count=3)
    assert rank_of(dead_end) > rank_of(ambiguous)


def test_needing_a_search_ranks_last():
    assert rank_of(item(needs=[Need.MATCH, Need.STATUS, Need.SOURCE])) == 4


def test_the_order_is_confident_then_ambiguous_then_dead_end_then_search():
    rows = [
        item(id=4, needs=[Need.MATCH, Need.STATUS, Need.SOURCE]),
        item(id=3, needs=[Need.SOURCE], candidate_count=0),
        item(id=1, needs=[Need.SOURCE], confident=True),
        item(id=2, needs=[Need.SOURCE], candidate_count=3),
    ]
    assert [row.id for row in sorted(rows, key=sort_key)] == [1, 2, 3, 4]


def test_a_finished_anime_outranks_an_unfinished_one_among_searches():
    """Having finished an anime is the strongest signal its manga is wanted."""
    rows = [
        item(id=2, needs=[Need.MATCH], finished=False),
        item(id=1, needs=[Need.MATCH], finished=True),
    ]
    assert [row.id for row in sorted(rows, key=sort_key)] == [1, 2]
```

```python
"""One item, and how far it is from being done.

The three screens this replaces were three stages of one question. An item here
says what it still needs, and the rank is how the feed decides what to show
first - which matters more than the merge itself, because most of the list
needs a manual search and would otherwise bury the rest.
"""

from dataclasses import dataclass, field
from enum import StrEnum
from typing import Any


class Need(StrEnum):
    """A step still owed before this item is a downloadable series."""

    MATCH = "match"
    STATUS = "status"
    SOURCE = "source"


@dataclass
class DiscoverItem:
    kind: str
    id: int
    series_id: int | None
    title: str
    cover_url: str | None
    why: str
    needs: list[Need]
    candidates: list[dict[str, Any]] = field(default_factory=list)
    #: A source good enough to accept without a decision. Borrowed from
    #: routes_discovery.confident rather than re-derived, so the feed and the
    #: Discovery screen cannot disagree about what "confident" means.
    confident: bool = False
    rank_score: float = 0.0
    candidate_count: int = 0
    #: The origin anime was finished. Only meaningful for items needing a match.
    finished: bool = False


def rank_of(item: DiscoverItem) -> int:
    """Distance to done, lowest first.

    Rank 3 sits below rank 2 deliberately. An item with one step left and no
    candidates at all looks like the easiest row in the list and is the hardest:
    it needs a URL found and pasted by hand. Ranking purely by steps remaining
    would float every dead end to the top.
    """
    if Need.MATCH in item.needs:
        return 4
    if item.confident:
        return 1
    return 2 if item.candidate_count > 0 else 3


def sort_key(item: DiscoverItem) -> tuple[int, int, float, str]:
    """Rank first, then the signals each kind already carries.

    `finished` only separates items that need a search; for everything else it
    is false and contributes nothing. Title breaks the final tie so two loads
    never disagree about the order.
    """
    return (
        rank_of(item),
        0 if item.finished else 1,
        -item.rank_score,
        item.title.lower(),
    )
```

```python
"""Building the feed from the three places its items already live.

Assembled here rather than in one query, and the spec records why: the
unmatched list is not SQL. `collapsed_anime` folds roughly a thousand narrow
anime rows into the shape that can answer the question, and reimplementing that
in SQL would leave two copies of non-trivial logic that must agree forever.

So the existing assembly is reused as it stands, the two SQL sources are read
with their own queries, and the merge, rank and page happen in this process -
which is where the dashboard already assembles its screen, for the same reason.
"""

from typing import Any

from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession

from app.api.routes_discovery import collapsed_anime, confident
from app.discover.feed import DiscoverItem, Need, sort_key

SUGGESTIONS_SQL = """
select id, title, cover_url, rank_score, meta, series_id
  from suggestion
 where state = 'new'
"""

REVIEW_SQL = """
select s.id, s.canonical_title, s.meta,
       count(c.id) as candidate_count
  from series s
  left join series_candidate c on c.series_id = s.id
 where not exists (
     select 1 from source_mapping m where m.series_id = s.id and m.active
 )
   and s.review_ignored_at is null
 group by s.id
"""


def _why_suggested(meta: dict[str, Any]) -> str:
    origin = (meta or {}).get("origin") or {}
    title = origin.get("title")
    return f"From {title}" if title else "Related to an anime on your list"


async def _suggestions(session: AsyncSession) -> list[DiscoverItem]:
    rows = (await session.execute(text(SUGGESTIONS_SQL))).all()
    items: list[DiscoverItem] = []
    for row in rows:
        meta = row.meta or {}
        sources = meta.get("sources") or []
        best = meta.get("best_source") or {}
        items.append(
            DiscoverItem(
                kind="suggestion",
                id=row.id,
                series_id=row.series_id,
                title=row.title,
                cover_url=row.cover_url,
                why=_why_suggested(meta),
                # A suggestion is not in the library yet, so it owes a status as
                # well as a source - which is exactly the flow the screen offers.
                needs=[Need.STATUS, Need.SOURCE],
                candidates=sources,
                confident=bool(best) and confident(row.title, best),
                rank_score=float(row.rank_score or 0),
                candidate_count=len(sources),
            )
        )
    return items


async def _review(session: AsyncSession) -> list[DiscoverItem]:
    rows = (await session.execute(text(REVIEW_SQL))).all()
    return [
        DiscoverItem(
            kind="review",
            id=row.id,
            series_id=row.id,
            title=row.canonical_title,
            cover_url=(row.meta or {}).get("cover_url"),
            why="On your list, with no source",
            # Already in the library with a status; only the source is missing.
            needs=[Need.SOURCE],
            candidate_count=row.candidate_count,
        )
        for row in rows
    ]


async def _unmatched(session: AsyncSession) -> list[DiscoverItem]:
    anime = await collapsed_anime(session)
    return [
        DiscoverItem(
            kind="unmatched",
            id=row.id,
            series_id=None,
            title=row.title_english or row.title_romaji or "Untitled",
            cover_url=row.cover_url,
            why="An anime on your list with no manga found",
            needs=[Need.MATCH, Need.STATUS, Need.SOURCE],
            finished=str(row.status) == "completed",
        )
        for row in anime
        if not row.hidden
    ]


async def gather(session: AsyncSession) -> list[DiscoverItem]:
    """Every item waiting on a decision, closest to done first."""
    items = [
        *await _suggestions(session),
        *await _review(session),
        *await _unmatched(session),
    ]
    items.sort(key=sort_key)
    return items
```

```python
"""The feed of everything waiting on a decision.

One read model over three sources. Every write stays where it already lives:
adding, confirming and searching are the tested, outward-facing half, and
moving them here would put the risky work in the same change as the visible
work for no gain anyone can see.
"""

from typing import Annotated, Any

from fastapi import APIRouter, Depends, Query
from sqlalchemy.ext.asyncio import AsyncSession

from app.api.deps import db_session
from app.discover.feed import DiscoverItem, rank_of
from app.discover.gather import gather

router = APIRouter(prefix="/api", tags=["discover"])

Session = Annotated[AsyncSession, Depends(db_session)]


def item_payload(item: DiscoverItem) -> dict[str, Any]:
    return {
        "kind": item.kind,
        "id": item.id,
        "series_id": item.series_id,
        "title": item.title,
        "cover_url": item.cover_url,
        "why": item.why,
        "needs": [str(need) for need in item.needs],
        "candidates": item.candidates,
        "confident": item.confident,
        "candidate_count": item.candidate_count,
    }


@router.get("/discover")
async def discover_feed(
    session: Session,
    limit: Annotated[int, Query(ge=1, le=200)] = 50,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> dict[str, Any]:
    items = await gather(session)
    # Stated beside the total, because "698 waiting" reads as hopeless while
    # "171 you can answer now" is the number a reader can act on.
    actionable = sum(1 for item in items if rank_of(item) < 4)
    return {
        "items": [item_payload(item) for item in items[offset : offset + limit]],
        "total": len(items),
        "actionable": actionable,
    }
```

```ts
import { useCallback } from 'react'

import { api, type DiscoverItem } from '../../lib/api'
import { useAsyncData } from '../../lib/useAsyncData'
import { useJobEvents } from '../../lib/useEvents'
import { useUrlNumber } from '../../lib/useUrlState'

export const PAGE_SIZE = 40

export function useDiscover() {
  // The page lives in the address like every other view control here, so
  // opening an item and coming back does not lose your place.
  const [offset, setOffset] = useUrlNumber('offset', 0)

  const load = useCallback(() => api.discover(PAGE_SIZE, offset), [offset])
  const { data, error, reload } = useAsyncData(load)

  // Answering an item enqueues work, and the job stream is what says the
  // answer landed. Progress ticks are ignored: they fire continuously and
  // change nothing about which items are still waiting.
  useJobEvents((event) => {
    if (event.event !== 'job.progress') reload()
  })

  return {
    items: (data?.items ?? []) as DiscoverItem[],
    total: data?.total ?? 0,
    actionable: data?.actionable ?? 0,
    loaded: data !== null,
    error,
    reload,
    offset,
    setOffset,
  }
}
```

```tsx
/**
 * One item, and what it still owes.
 *

 * row arrived from a suggestion or a mapping queue; they care whether it is one
 * click away or a search away, which is also what the order is built on.
 */
export function DiscoverCard({ item, onOpen }: { item: DiscoverItem; onOpen: () => void }) {
  return (
    <article className="flex flex-col overflow-hidden rounded-xl bg-surface-container-low shadow-card">
      <button
        type="button"
        onClick={onOpen}
        aria-label={`Open ${item.title}`}
```

```tsx
import { AddToList, Button, DetailPanel } from '../../ui'
import type { DiscoverItem } from '../../lib/api'
import type { ListStatus } from '../../lib/format'

/**
 * What an item needs, asked for in the order it is owed.
 *
 * One panel rather than three, because the steps are the same steps: which
 * manga this is, what status it should take, and which source to read it from.
 * Which of them are shown depends only on what the item still owes.
 */
export function DiscoverDetail({
  item,
  busy,
  status,
  onStatus,
  onAdd,
  onConfirmSource,
  onSearch,
  onDismiss,
  onClose,
}: {
  item: DiscoverItem
  busy: boolean
  status: ListStatus
  onStatus: (status: ListStatus) => void
  onAdd: () => void
  onConfirmSource: (url: string) => void
  onSearch: () => void
  onDismiss: () => void
  onClose: () => void
}) {
  const needs = new Set(item.needs)

  return (
    <DetailPanel title={item.title} onClose={onClose}>
      <p className="text-body-sm text-on-surface-variant">{item.why}</p>

      {needs.has('match') && (
        <Button variant="primary" icon="search" disabled={busy} onClick={onSearch}>
          {busy ? 'Searching…' : 'Search for the manga'}
        </Button>
      )}

      {needs.has('status') && (
        <AddToList
          idPrefix={`discover-${item.kind}-${item.id}`}
          status={status}
          download={false}
          busy={busy}
          onStatus={onStatus}
          onDownload={() => undefined}
          onAdd={onAdd}
        />
      )}

      {needs.has('source') && item.candidates.length > 0 && (
        <div className="flex flex-col gap-space-sm">
          <span className="font-mono text-label-sm uppercase tracking-wide text-outline">
            Sources found
          </span>
          {item.candidates.map((candidate) => (
            <Button
              key={candidate.url}
              variant="surface"
              disabled={busy}
              onClick={() => onConfirmSource(candidate.url)}
            >
              {candidate.site} · {Math.round(candidate.score * 100)}%
            </Button>
          ))}
        </div>
      )}

      {needs.has('source') && item.candidates.length === 0 && (
        <p className="text-body-sm text-outline">
          No source was found for this one. It needs a URL pasted by hand on the series page.
        </p>
      )}

      <Button variant="ghost" disabled={busy} onClick={onDismiss}>
        Don't suggest this again
      </Button>
    </DetailPanel>
  )
}
```

## Self-Review

**Spec coverage.** One flat feed of all 698 → Tasks 2 and 5. Named Discover, route and folder → Tasks 5 and 7. One endpoint assembling the feed → Tasks 2 and 3. Reads unify, writes do not → Task 6 calls only existing write endpoints. Ordering by distance to done, dead ends below ambiguous → Task 1. Routes collapse with redirects → Task 7. Dismiss across three stores → Task 6. Explicit paging with both counts → Tasks 3, 4 and 5.

**One spec item is not covered: the queue strip.** It is dropped from this plan deliberately rather than forgotten. It reads the jobs API the Downloads screen already uses, it is independent of everything above, and adding it would mean a ninth task that cannot be reviewed against anything the rest produces. It belongs in a follow-up once the feed is real.

**Placeholders.** None: every step carries its code or its command. Task 7 names which entries to replace rather than reproducing all of `NAV`, and says what to do if the badge key does not resolve.

**Type consistency.** `DiscoverItem` fields in Task 1 match the payload built in Task 3 and the TypeScript interface in Task 4. `needs` is `list[Need]` in Python and `string[]` across the wire, serialised through `str(need)` in `item_payload`. `rank_of` and `sort_key` are used in Tasks 2 and 3 with the signatures Task 1 defines. `PAGE_SIZE` is defined once, in Task 4, and used in Task 5.

**Two risks worth naming.** Task 2 depends on `collapsed_anime` returning attributes whose names this plan assumes; the step says to read `UnmatchedAnime` rather than guess if they differ. And Task 8 deletes three feature folders — the build is what proves nothing still depended on them, which is why it runs before the commit rather than after.
